# 开发顺序与验收清单

本文件供接手实现的 AI/开发者逐项执行。输入规格：[产品逻辑](PRODUCT_LOGIC.md)、[系统架构](ARCHITECTURE.md)、[UI 设计](UI_DESIGN.md)。禁止把“编译通过”当成产品完成。当前仓库为旧版原型，下面列的是**目标**。

## 1. 开工前核对

1. 查实际板卡丝印、屏幕类型/分辨率/形状、触摸芯片及厂商 ESP-IDF 示例。当前仓库按 ESP32-C6 480×480 触摸 AMOLED 写，用户描述 2.13 寸 OLED；不同硬件应先更新 `main/user_config.h`、BSP 与 UI 基线。厂商页面列 CO5300/CST9220，当前代码用 SH8601/CST9217 接口，必须实机验证兼容性。
2. 确认 Herdr 与 `herdr-restful` 的版本和 `/api/v1/agents`、`/api/v1/panes`、`/api/v1/health`、agent read/keys/prompt 的响应。把测试样本固定在仓库，不要把模拟响应当成真机实测。
3. 先确定部署安全边界：设备能否访问主机；HTTP/HTTPS、鉴权 token、局域网或隧道。无鉴权时不能公开服务地址到公网。

## 2. 分阶段交付

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| A 硬件与文字 | BSP、触摸、中文字体、QR | 真机显示 480×480 完整画面；中文正常；触摸校准；手机扫描二维码可进配网页。 |
| B 只读面板 | 配网、健康、四宫格、详情 | 只列 agent；五种 Herdr 状态原样映射；0/1/4/5/24/25 会话与断线场景正确；无可执行假按钮。 |
| C 网关决策 | 新增 `/api/v1/panel`、CLI 适配器、上下文令牌、去重 | 用真实 Claude/OpenCode/Pi 的代表性审批/提问屏验证；旧卡、错误 agent、超时均拒绝发键。 |
| D 设备动作 | 确认页、发送/回读、错误状态 | 每次手势最多发一个 `request_id`；结果未知不自动重试；动作后刷新详情。 |
| E 视觉与稳定性 | 动画、亮度、设置、压力测试 | 真机阅读/触摸/扫码通过，连续运行、掉线恢复、内存水位合格。 |

架构门槛贯穿每个阶段：HTTP 只在网络任务，LVGL 只在 UI 任务；队列满不阻塞触摸回调；所有详情响应绑定 `server_id + terminal_id + selection_epoch`，不可用列表刷新用的 `store_generation` 误杀有效详情；内存峰值和各任务栈水位必须记录。

## 3. 接口样本与关键断言

至少准备以下 JSON 样本：5 种 Herdr 状态；agent 缺失字段；普通 shell pane；跨 workspace 移动导致 `pane_id` 变化但 `terminal_id` 不变；同一 terminal 换 agent；超长中文标题/路径；未知状态；24+ agent；`health: degraded`；畸形 JSON；含 ANSI/控制字符的输出。

动作网关用例至少覆盖：

1. `blocked + 当前 Claude 审批卡 + allow_once`：动作成功发送一次，返回的现场指纹匹配；2 次同 `request_id` 只能发送一次。
2. `blocked + 一般问题`：允许/拒绝都不出现在 `choices`；设备按钮禁用。
3. `blocked + 新提示替换旧提示`：旧 `context_token` 返回 409；主机没有收到任何旧按键。
4. `done/idle + continue`：确认页显示完整 prompt；被另一个操作改成 blocked 后，原继续请求被拒绝。
5. `working/unknown/离线`：所有决策请求拒绝，设备无活动按钮。
6. `terminal_id` 指向新 agent、`pane_id` 改变、服务重启导致 `server_id` 改变：旧卡/旧 token 都失效。
7. OpenCode `once/always/reject`、Claude 当前版本提示、Pi 无审批扩展：适配器分别正确显示选项；Pi 不凭空出现允许按钮。
8. HTTP 超时发生于发键后：设备只显示“结果未知”，不自动发送第二次；网关重放同 `request_id` 不重发。
9. 结果响应 `accepted` 不被 UI 误写成“已批准”；只有后续现场证据足够时显示“已处理”。
10. 提示过长、影响范围无法完整描述、无法识别的 agent CLI 版本：网关 `choices=[]`，用户在主机处理。
11. 同一 `request_id` 换请求体必须拒绝；网关在去重记录落盘后、发键前崩溃，恢复后返回 `uncertain` 且不补发。
12. 详情请求飞行期间列表刷新仍能正常显示详情；快速点开 A→返回→点开 B 后，A 的迟到响应不可覆盖 B。
13. 塞满 `control_q`/`ui_evt_q` 后触摸回调不阻塞；动作结果不能被丢弃；峰值堆和最大连续块仍满足预算。
14. A 会话动作正在发送时，B 会话的确认不能排入第二个动作；A 的队列项被 worker 取走后仍保持全局未决占位。
15. 401/403、409 `stale_context`、409 `id_conflict`、422、503、无响应分别按契约显示；列表鉴权失败不能出现“暂无会话”。

## 4. 页面与真机检查

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| U01 | 首次开机 | 显示二维码、SSID、手动网址；码能被手机扫码。 |
| U02 | 配网页提交错误 IP/端口/空 SSID | 网页提示具体问题，屏幕不误报“已连接”。 |
| U03 | 同时有 blocked/working/done/idle | 四格分别显示文字、图形、颜色；图标不遮住名字。 |
| U04 | 第 5 个 agent 出现 | 可翻到第 2 页，页码正确；刷新不乱序跳卡。 |
| U05 | 点卡片、快速滑动 | 点击进入正确 `terminal_id`；滑动只翻页不误进入详情。 |
| U06 | 详情被新状态刷新 | 按钮条件立即更新；在确认页时取消过期操作。 |
| U07 | 允许/拒绝/继续确认 | 能看清 agent、项目、请求内容/影响或继续提示词；取消不发请求。 |
| U08 | 切断 Wi-Fi/REST/Herdr | 保留最后快照并显示旧数据/具体故障，所有动作禁用。 |
| U09 | Wi-Fi/REST 恢复 | 自动全量刷新；旧动作不自动重发。 |
| U10 | 进入菜单 | 连接/显示/关于/重新配网可达；密码、token 不显示。 |
| U11 | 开启减少动画、降亮、唤醒 | 持续动效停止，触摸恢复亮度，交互仍流畅。 |
| U12 | 中文、长英文、emoji、无字形字符 | 无覆盖/裁切导致关键内容看不到，布局不崩溃。 |

视觉验收应保存首页、详情（审批/非审批）、确认、配网、离线、空状态、设置的 480×480 截图；再做真机阅读与触摸测试。二维码、触摸和实际显示芯片兼容性只能在真机确认。

## 6. 完成定义

只有 A–E 全部通过、真实 agent UI 的适配器用例通过、文档中的状态/动作条件与固件一致，才可在 README 宣称“可处理审批”。若网关尚未实现，允许先交付只读四宫格，但三个决策按钮须隐藏或禁用，并在交付说明中明确阶段。任何模拟器/单元测试通过都不能代替真实主机与真机的端到端验证。
