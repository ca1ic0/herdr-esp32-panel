# 运行时设置与声音交互规格

版本：v2 目标规格（2026-10-01）。给实现 ESP-IDF 固件、主机 panel 网关和验收用的 AI 阅读。本文件同时包含已落地功能及后续验收目标；具体进度见末尾“实施状态”。产品/页面/模块的上层约束分别见 [PRODUCT_LOGIC.md](PRODUCT_LOGIC.md)、[UI_DESIGN.md](UI_DESIGN.md)、[ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 真实能力与目标

- 本仓库对应 Waveshare ESP32-C6-Touch-AMOLED-2.16。厂商资料列出 ES8311 音频编解码器、扬声器放大器及外接扬声器 2PIN 焊盘；厂商 ESP-IDF `07_Audio_Test` 演示录音和扬声器播放。**必须核查实际成品是否已接扬声器**，以及当前板级版本的 I2S/使能引脚。只有芯片和焊盘、没有扬声器的板子不会发出可听声音。[硬件资料](https://docs.waveshare.com/ESP32-C6-Touch-AMOLED-2.16) · [厂商 ESP-IDF 音频示例](https://docs.waveshare.com/ESP32-C6-Touch-AMOLED-2.16/ESP-IDF)
- Herdr 官方有两类内置提示音：`request`（agent 需要输入）和 `done`（agent 完成工作）。上游源码内嵌 `assets/sounds/request.mp3`、`done.mp3`，可单独配置音效开关及文件。**目标是使用同一音频素材，并尽量使用同一事件语义**。现有 panel `overview` 只有状态快照，不能证明 Herdr 桌面程序究竟播放过哪一次音。要达到完全一致的触发时机，主机需要提供来自 Herdr 通知源的事件；单靠设备比较两次快照只能近似。[Herdr 声音配置](https://herdr.dev/docs/configuration/) · [Herdr 声音源码](https://github.com/herdrdev/herdr/blob/master/src/sound.rs)
- 声音只是提醒。没有扬声器、用户静音、音频驱动故障时，四宫格状态、视觉提示、审批确认和网络轮询照常工作。声音绝不能提交、确认或重试 agent 动作。

## 2. 设置数据模型：默认值、范围、编辑入口

所有数值先做边界校验，再写入内存快照；屏幕立即显示新值和效果。保存到 NVS 成功才显示“已保存”，失败恢复上一个已保存值并显示“保存失败”。正常修改以下设置**不重启设备**。设备保留出厂默认与用户值两层，不把菜单中显示的当前值当作编译期常量。

| 键（建议 `panel_prefs_t` 字段） | 默认 / 范围 | 屏幕入口 | 生效与持久化 |
| --- | --- | --- | --- |
| `sound_enabled` | 开 / 开关 | 快捷菜单；设置→声音 | 立即停播、清空未播队列；NVS。 |
| `sound_volume` | 50% / 0–100%，步长 10% | 设置→声音；测试页 | 立即调整 ES8311 输出音量；NVS。0% 等于静音。 |
| `sound_request` | 开 / 开关 | 设置→声音 | 立即影响新事件；NVS。 |
| `sound_done` | 开 / 开关 | 设置→声音 | 立即影响新事件；NVS。 |
| `sound_scope` | 全部 / `全部`、`仅当前页`、`仅选中会话` | 设置→声音 | 立即影响新事件；NVS。未选中会话时“仅选中”不发声。 |
| `agent_sound_override` | 继承 / 每个 `agent` 类型的 `继承`、`开`、`关` | 设置→声音→Agent | 立即影响新事件；NVS；按类型，不按动态 `terminal_id` 保存。 |
| `quiet_enabled` | 关 / 开关 | 设置→声音→免打扰 | 立即影响新事件；NVS。 |
| `quiet_start`, `quiet_end` | 22:00–08:00 / 15 分钟步进 | 设置→声音→免打扰 | 仅在已同步本地时区时间时生效；NVS。跨午夜有效；起止相同表示全天静音，并在 UI 明示。 |
| `utc_offset_minutes` | +480（UTC+08:00）/ −720 至 +840，步长 15 分钟 | 设置→声音→免打扰 | 立即用于免打扰计算；NVS。固定偏移不自动处理夏令时，发生变化时用户手动调整。 |
| `brightness` | 45% / 10–100%，步长 5% | 快捷菜单；设置→显示 | 拖动时即时预览，松手后延迟合并 NVS 写入；NVS。 |
| `idle_dim_seconds` | 60 秒 / 关、30、60、120、300 秒 | 设置→显示 | 立即重设静置计时；NVS。确认页与二维码页不降亮。 |
| `dim_brightness` | 15% / 5–50%，不高于常态亮度 | 设置→显示 | 立即应用于已降亮画面；NVS。 |
| `reduce_motion` | 关 / 开关 | 设置→显示 | 立即停/启动装饰动画；NVS。 |
| `visual_alert` | 开 / 开关 | 设置→显示 | 只控制额外的两次边框脉冲；状态文字、形状、颜色始终显示；NVS。 |
| `overview_interval` | 3 秒 / 2、3、5、10 秒 | 设置→会话 | 下一轮生效；NVS。事件轮询另受服务端保留期约束。 |
| `card_order` | 固定位置 / `固定位置`、`待处理优先`、`最近更新` | 设置→会话 | 立即重排首页，保留选中 `terminal_id` 可见；NVS。 |
| `hide_idle` | 关 / 开关 | 设置→会话 | 立即筛选，顶部仍显示全部/已隐藏数量；NVS。 |
| `continue_prompt` | `继续当前任务，并先说明下一步。` / UTF-8 ≤ 160 字节 | 临时手机配置页 | 保存后下次打开确认页生效；NVS。已有确认页冻结的文本不变。 |

`agent_sound_override=开` 的含义是允许该类型在总开关及免打扰允许时发声，**不能绕过总静音**。Herdr 本机的声音配置与这台设备的设置独立：用户可选择仅主机响、仅面板响或两边都响；面板不修改主机 Herdr 配置。默认全部发声只在明确观察到新的事件时生效，首次连接不会把历史 `blocked/done` 当成新事件。

Wi-Fi SSID/密码、网关 URL/token 是连接配置，不走音量设置通道。用户选择“连接→编辑连接”时，设备设置一次性标记并软重启到有时限的 WPA2 配置热点，屏幕显示 QR；手机提交后保存并软重启到 Wi-Fi/网关，不清除其它偏好。重新配网/清除凭据仍单独二次确认。临时网页同时可编辑长 `continue_prompt`；5 分钟到期自动重启并关闭 AP、DNS、HTTP。屏幕上任何设置页都能返回，不强制用手机才能改亮度、静音、音量或免打扰。

`continue_prompt` 留空时沿用网关默认值；手机提交的非空文本最多 160 个 UTF-8 字节，存到设备 NVS。设备只在网关给出 `source=new_prompt` 的继续卡片时替换详情与确认页文案，并把同一文本附在动作请求里。网关仍验证当前会话、状态、现场指纹和上下文令牌；终端原生“继续”选项 `source=terminal_ui` 只发经过适配的按键，不发送自定义提示词。手机页面中空字段保留原连接值，“恢复网关默认提示词”会清除此设备的覆盖值。

## 3. 动态更新的精确流程

```text
触摸改变值 → UI 对本地副本做范围校验与即时预览
  → control_q 投递 SET_PREF{完整候选版本, changed_mask, generation}
  → config_service 校验整份配置并 NVS 提交
  → CONFIG_RESULT{generation, accepted/rejected, 实际值}
  → UI 显示已保存或回滚；消费者只订阅已接受的设置快照
```

只有 UI 线程操作 LVGL；只有配置服务写 NVS；音频任务只接收设置快照，不直接访问 UI 控件。高频滑杆预览直接调用线程安全的亮度/音量命令；连续拖动最多每 150 ms 发送一次预览，松手后 500 ms 合并成一次 NVS 写入，避免磨损。互相独立的两项快速修改不能用旧完整快照覆盖新值：配置服务按 `changed_mask` 合并到最新版本，或用版本号拒绝过期命令并让 UI 重取。所有队列非阻塞；满时显示“忙，请稍后”，UI 不得假报已保存。断电后只恢复最后成功提交的值。配置 schema 有版本号与迁移函数，旧键缺失取默认，超范围值回退默认并记录非敏感诊断。

临时预览与事件播放器之间有优先级：用户测试音最高；真正的 `request` 高于 `done`；重复低优先级事件可丢弃。音量调整影响正在播放的音效；静音须在 100 ms 内停播。音量控制上限还要按扬声器实测避免削波，100% 不是数字放大到失真。

## 4. Herdr 音效与播放文件

| 设备音效 | 官方素材 | 业务事件 | 禁止触发 |
| --- | --- | --- | --- |
| `request` | `assets/sounds/request.mp3` | Herdr 产生“需要输入/阻塞”通知；若网关无原生通知源，使用可靠的同一 agent `非 blocked → blocked` 转移并标记为近似来源。 | 冷启动初次快照、重复轮询、网络恢复补扫、仅打开详情、`blocked` 内部文字更新。 |
| `done` | `assets/sounds/done.mp3` | Herdr 产生“任务完成”通知；近似模式只在同一 agent `working → done` 转移发出。 | 初次快照、`idle` 刷新、仅打开已完成详情、动作 HTTP 返回 `accepted`。 |

音频资产应固定到经审核的 Herdr 源码提交，记录文件 SHA-256、来源 URL、许可证和素材归属；不要在构建时从 `master` 动态下载。2026-10-01 参考源码提交 `d6b40d4edd550ccea081f089605a64314f8c8b27`：`done.mp3` SHA-256 `cb9c93492c808e33946edac2ab5915758267e65914bc4b794a5ca6dc6e655741`，`request.mp3` SHA-256 `44c077ce28a0a48cec29da204beb627fd17140e5bde1f92dbaecf3d478bdda6f`。上游仓库标 Apache-2.0；纳入发行包前复核音频资产是否有单独来源说明，并保留许可证/署名。**同素材**不等于**同声压**：ES8311、外接扬声器、音量设定和外壳都会影响听感。

在构建阶段用受控脚本把两段 MP3 解码、降采样/混音为板级播放格式（例如 16 kHz、16-bit、单声道 PCM），把原始资产及转换参数的哈希写入 manifest；运行时无需 MP3 解码器。每段 PCM 的大小、flash/堆预算和音质由真机检查确定；播放时分块从 flash 送 I2S，不整段复制到堆。若转换后的听感明显不同，应选兼容的更高采样率并重新测内存。厂商示例的 I2S 引脚是**示例板版本**，不能仅凭网上头文件覆盖本仓库 `user_config.h` 的显示/触摸引脚。

## 5. 网关事件 API（本产品新增，不是 Herdr 官方 API）

仅靠 `/overview` 的当前状态无法保证“响一次”。主机 panel 网关增加 `GET /api/v1/panel/events?after=<cursor>&limit=16`，与其它 panel API 使用同一设备 Bearer 鉴权。响应固定上限 4 KiB：

```json
{
  "schema_version": 1,
  "server_id": "host-a-boot-42",
  "latest_cursor": "evt-0000000000000094",
  "next_cursor": "evt-0000000000000094",
  "has_more": false,
  "gap": false,
  "events": [
    {
      "event_id": "evt-0000000000000094",
      "terminal_id": "term-a",
      "agent": "claude",
      "kind": "request",
      "source": "herdr_notification",
      "occurred_at": "2026-10-01T10:00:00Z",
      "age_ms": 350
    }
  ]
}
```

`kind` 仅 `request|done`；`source` 为 `herdr_notification|state_transition`。网关若拿不到 Herdr 原生通知事件，必须在服务端按 `server_id + terminal_id + agent` 保存前次状态，只对可靠转移生成近似事件；不能把每个当前 `blocked` 或 `done` 都变成新事件。事件 ID 在同一 `server_id` 中严格有序，保留至少 10 分钟、至少 256 条。`after` 缺失表示**建立基线**：只返回最新游标，不返回历史事件，`next_cursor=latest_cursor`。后续带游标仅返回更晚的事件，按顺序最多 16 条；`next_cursor` 是本页最后一条的 ID，`has_more=true` 时设备继续以它请求下一页，**不能跳到 `latest_cursor` 丢弃中间事件**。游标超出保留期返回 `gap=true`、最新游标、空事件，此时 `next_cursor=latest_cursor`；设备显示“提醒可能遗漏”但不补播。`server_id` 变化时设备丢弃旧游标、重新建立基线。网关不返回终端输出、审批文本或音频字节。

设备成功解析完整一页响应后按顺序过滤事件，再把 `next_cursor` 写入内存；队列满记录丢弃计数并仍推进游标，不让通知拖慢决策动作。HTTP 超时或畸形响应不推进游标。重复 `event_id`、乱序、超过 30 秒的事件不播放；不把收到事件的时间当发生时间。时钟未同步时，网关可另给可信事件 age 或设备保守不播过期不明事件；免打扰时间功能在时钟未同步时采取静音并提示“时间未同步”。正常模式下每 2 秒拉事件；优先级低于动作/详情，高于普通 overview 刷新。无法连接事件 API 时显示视觉状态但不自行把状态快照当音效事件。

`age_ms` 是必填字段，由网关按自身时钟计算。设备据此丢弃旧事件，不依赖首次开机尚未同步的时钟。

## 6. 播放任务与故障处理

```text
panel_worker ── 已鉴权事件 ──> event_filter ── 有界 audio_q(4) ──> audio_task
                               ↑ 设置快照                         ├─ ES8311 codec
                               ↑ 选中/当前页身份                  └─ I2S TX → 功放 → 扬声器
```

- `audio_task` 是 ES8311、I2S TX、播放状态的唯一属主。启动时初始化一次，切后台/设置页无需重建；用 ESP-IDF I2S/厂商 codec BSP，记录具体板版引脚和使能时序。音频任务优先级低于 UI 触摸与关键网络动作，写 I2S 使用小分块；任何音效不得持有 LVGL/store 锁。
- 同一 `terminal_id + kind` 在 15 秒内仅播放一次；全局相邻音效间隔至少 500 ms。`request` 到来时可中断或压掉排队的 `done`，但不叠放两段音。队列满优先保留新的 `request`。多个 blocked 同时到来只响一次并在首页显示计数，不把扬声器当报警器持续循环。
- “试听”按钮只本机播放被选中的 `request/done` 素材，不向网关发动作，也不改变 Herdr 会话状态。试听可在音量为 0% 时要求先调高音量；静音总开关下允许一次试听，但 UI 必须显示“试听不改变静音设置”。
- 扬声器未接、codec 初始化失败、I2S 写入超时或资源不足时音频降级为不可用，菜单显示“声音不可用 · 查看硬件”；不在每轮轮询反复初始化或阻塞 UI。离线不播放旧事件；恢复先建立事件基线。硬件缺失不影响审批安全路径。

## 7. 例子与验收边界

1. 面板第一次连接时 A 已 `blocked`、B 已 `done`：显示两种状态，**不响**。后来 A 从 `working` 变成 `blocked`：只响一次 `request`；持续 20 次相同快照不再响。
2. 用户在主页点静音：当前声音 100 ms 内停止，图标即时更新；关静音后不会补播静音期间旧事件。重启仍保留设置。
3. 声音设为仅当前页，A 在第 2 页发生新请求而用户在第 1 页：只更新待处理数和视觉提示，不响；翻到第 2 页不会补响。
4. 22:00–08:00 免打扰开启；23:00 收到 `request`：不响。时间未同步时也不响并有明确提示；状态和审批按钮仍按正常规则显示。
5. 网关重启、游标缺口、Wi-Fi 断开恢复：不播放历史通知；新的可靠事件继续响。声音 API 401/协议错误不能解释成“没有事件”。
6. 断电发生在音量设置 NVS 提交前：重启使用上次已保存音量，不显示“已保存”。亮度与音量连续快速调整不应彼此覆盖。

## 8. 实施状态（2026-10-01）

- 固件已接入分组设置、NVS 持久化、静音/音量/亮度即时预览、降亮、减少页面动效、待处理卡片脉冲、试听、ES8311/I2S PCM 播放及事件游标过滤。`panel_worker` 是网络与 NVS 写入者，音频任务独占 codec/I2S。
- 相邻 `herdr-restful` 网关已提供鉴权的 `/events`，从成功读取的完整 Herdr 快照生成 `state_transition` 事件；**尚无 Herdr 原生通知源**，因此时机与桌面端不能保证完全相同。
- 屏幕“扫码编辑连接/继续提示词”现通过软重启进入 5 分钟热点，手机页面可修改并保留未填写的旧值；继续提示词由设备 NVS 覆盖并在主机验证后发送。配置服务使用字段级合并，滑杆松手后保存，尚未加入 500 ms 写入合并。连接编辑完成后仍采用整机软重启，尚未优化为仅重连 Wi-Fi/网关。
- 本地没有 ESP-IDF 工具链和成品硬件。固件编译交由 GitHub Actions；扬声器焊接、I2S 引脚、显示芯片、音量听感、触摸与二维码仍须真机验收。不能仅凭代码或网关单元测试宣称这些项目通过。
